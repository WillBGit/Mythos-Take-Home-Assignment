# Take-Home-Assignment

The program I have created is a simple pdf converter that turns a csv file into a list of pdf cover letters for the specified companies and individuals in the file. In general when setting out to do this assignment, I wanted to focus on a generally simple solution without compromising too much efficiency. Given the time constraint having a system that would be feasible to implement and easy to debug was paramount. As well, given the focus on a joint python and javascript framework that was discussed during the first round of interviews, I felt it would be prudent to show my ability to use those languages in tandem. The general flow of this will be defined below.

# PYTHON SCRIPT csvReader.py

The python script is a straightforward implementation solely for the purpose of parsing the csv file, as python has a robust built in system for this parsing. The Python script first defines a person data type to store the relevant data for each person in the csv. This was done for ease of access and general code tidiness. The script then parses the csv file and stores it as a dict, where the row number is the key and the person data type instance is the value stored. This was a key decision I made, as while a list would have worked fine with the implementation, I wanted the ability to be able to access any person's data by its row number in O(1) time, that way if there were any issues with debugging I could quickly query for any data I need or certain subsets (say, data from row 500-600). Once this is converted to a dict, that dict is then dumped into a json file to be read by pdfConverter.js. This was done as it was the simplest efficient way to pass the data to the javascript code without running an internal server or some more convoluted solution.

# JAVASCRIPT SCRIPT pdfConverter.js

The javascript script handles the bulk of the work for this implementation. It first runs the python script to update the json file. I felt that while this does increase the runtime of the program by about a second, it would be a useful tool to have, both for when the script is run for the first time so only one terminal call will have to be made, and also for scalability so that if more rows were added to the csv the json could be updated before the converter ran. Once the python script is run, the program reads in the json file and parses it back into a dict (see reason for dictionary usage above). From here, the script goes through each entry in the dict and runs the generateCoverLetter method, which takes in the data from person and uses pdfkit to form the actual pdf, creating the page and text. While the text features for the pdf were very straightforward, one interesting thing I found while reading through the pdfkit documentation was the ability to embed data into the pdf. I thought this would be useful for any sort of debugging, as I could tell exactly which data was populating a given pdf and see what errors might be throwing it off. Additionally, being able to have a pdf creation and modification date built in would be useful both for me and the client for any sort of bookkeeping, so I added in the embedding following the syntax outlined in the pdfkit documentation. The generated pdfs are then put into the output folder, which is bundled with the code for this assignment.

# FUTURE IMPROVEMENTS GIVEN TIME

These are just a few features I was thinking of adding that I did not want to risk jeopardizing the functionality of the code to try out given the time I had.

One of the major things I would like to do is add a check before the python script is run in the javascript to see if the csv was updated before running it, and perhaps even having it use a watch to have it update the json automatically. Running the script every time doesn't seriously dampen the runtime, however automating the system would improve it, which would be especially useful if the amount of rows was exponentially increased. 

Another feature I found interesting from reading the pdfkit documentation was the registering of fonts for the pdf. I noticed that the document was given to us in Roboto, and I wanted to match this with my document. However I found registering the fonts for the pdfs was greatly increasing the runtime, so I decided to return to Courier font in order to meet the MVP efficiently.
